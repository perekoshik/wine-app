# 🍷 Подборка хороших вин – Streamlit-приложение (ДЗ-3, часть 4)

Приложение для сомелье сервиса по подписке. По 12 лабораторным признакам вина логистическая регрессия оценивает вероятность того, что вино «хорошее» (оценка экспертов не ниже 7), и решает, брать ли его в подборку.

Модель обучена в ноутбуке `HW3_MMDA.ipynb`: `StandardScaler` + `LogisticRegression` без весов классов. Порог по умолчанию 0.268 – это порог $t_{F_1}$, подобранный на валидации (задание 2.5). Модель внутри приложения не обучается, она только загружается из `model.joblib`.

## Что в папке


| Файл               | Что это                                                                 |
| ------------------ | ----------------------------------------------------------------------- |
| `app.py`           | приложение                                                              |
| `model.joblib`     | обученный пайплайн (scaler + логистическая регрессия)                   |
| `config.json`      | выбранный порог                                                         |
| `test.csv`         | тестовая выборка с `target`: по ней считаются метрики и диапазоны полей |
| `requirements.txt` | версии библиотек                                                        |




## Вкладки

1. Оценка одного вина – ввод 12 признаков (диапазоны и значения по умолчанию – min / max / медиана по `test.csv`, тип вина – переключатель «красное / белое»), вероятность и решение модели.
2. Модельные метрики – при движении порога пересчитываются матрица ошибок, precision, recall, F1 и точка на ROC- и PR-кривых. Есть пояснение для сомелье, что будет с подборкой при росте и падении порога.
3. Пакетное предсказание – загрузка CSV с признаками, таблица с вероятностью и решением для каждого вина, скачивание результата. Если не хватает столбцов, файл пустой или в нём нечисловые значения – выводится `st.error`, приложение не падает.
4. Что выучила модель – коэффициенты логистической регрессии (на стандартизированных признаках), отсортированные по значению.

Порог задаётся слайдером в боковой панели и общий для всех вкладок.

## Как запустить

Нужен Python 3.12 (проверено на 3.12.13). Из папки `wine_app`:

```bash
python3.12 -m venv .venv
source .venv/bin/activate          # на Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Приложение откроется на `http://localhost:8501`. Запускать можно из любой папки: пути к файлам строятся от `app.py` (`Path(__file__).parent`).

Версию `scikit-learn` лучше не менять: `model.joblib` сохранён в 1.9.1, в другой версии модель может не загрузиться или выдать предупреждение.

## Кэширование (задание 4.5)

- `load_model()` – `@st.cache_resource`. Streamlit перезапускает `app.py` при каждом действии пользователя. Без кэша модель читалась бы с диска на каждое движение слайдера. `cache_resource` хранит один и тот же объект на весь сервер и отдаёт его всем сессиям без копирования. Модели это и нужно: `predict_proba` её не меняет, значит делить её между пользователями безопасно, а копировать незачем.
- `load_test()` и `test_proba(_model, X)` – `@st.cache_data`. Он кэширует данные по значениям аргументов и каждому вызову отдаёт копию, поэтому если кто-то поменяет таблицу, остальные этого не увидят. Вероятности на test считаются один раз: при движении слайдера меняется только сравнение `proba >= threshold`, `predict_proba` заново не вызывается. Аргумент `_model` с подчёркиванием Streamlit не хеширует.
- Почему не `cache_data` для модели: он сериализует результат и на каждом вызове собирает копию заново из байтов, а это по сути тот же `joblib.load` на каждый перезапуск.
- Что будет без декоратора: `joblib.load` будет выполняться на каждый клик и на каждое движение слайдера. Приложение станет медленнее, и в памяти будет столько копий модели, сколько активных сессий.
- Обратная сторона `cache_resource`: если переобучить модель и перезаписать `model.joblib`, приложение продолжит отвечать старой. Нужно перезапустить сервер или нажать `C` (Clear cache), в облаке – `Reboot app`.
